# Validation Strategy

Because CareerPilot relies on Large Language Models (LLMs) for both its core interaction and its objective scoring, strict validation mechanisms must be documented to prove to academic examiners and B2B customers that the system is not merely generating "hallucinated" feedback.

## 1. Prompt Validation (The "Golden Dataset")
- **Mechanism:** A static dataset of 50 pre-recorded interview transcripts, covering various roles, will be established.
- **Validation Test:** Whenever the scoring system prompt is updated, the Golden Dataset must be re-processed by DeepSeek. The new scores must correlate ($R > 0.90$) with the historical baseline scores to ensure the AI has not become drastically stricter or more lenient due to prompt drift.

## 2. Context Relevance Validation
- **Mechanism:** The system's ability to fetch relevant web data via Tavily must be validated.
- **Validation Test:** For a sample of 20 Job Descriptions, the extracted web context (past interview questions) will be manually reviewed by domain experts (e.g., Senior Engineers) to rate the relevance on a scale of 1-5. An average relevance score of $> 4.0$ is required.

## 3. Feedback Actionability Validation
- **Mechanism:** Validating that the AI's feedback is actually useful to the student.
- **Validation Test:** A qualitative assessment where students rate the "Ideal Answer" generated by the AI as either "Helpful", "Neutral", or "Not Helpful". The system requires a $> 80\%$ "Helpful" rating across the pilot cohort to validate the DeepSeek prompt engineering.
